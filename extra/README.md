# Mini Redis 핵심 자료구조 3총사 심층 분석

Mini Redis가 내장 컬렉션(`dict`, `set`) 없이도 극도로 빠른 성능을 발휘하는 이유는, **해시맵(HashMap)**, **이중 연결 리스트(Doubly Linked List)**, **최소 힙(Min-Heap)**을 목적에 맞게 $O(1)$ 및 $O(\log N)$으로 유기적으로 결합했기 때문입니다.

---

## 1. 세 자료구조의 역할과 결합 방식

### ① 해시맵 (HashMap) — $O(1)$
* **역할**: "초고속 데이터 색인 (주소록)"
* **특징**: 데이터가 10개든 1,000만 개든 상관없이, 키 이름만 주면 단 한 번의 연산($O(1)$)으로 그 데이터가 있는 위치를 즉시 찾아냅니다.
* **한계**: 찾는 건 제일 빠른데, "어떤 게 가장 오래전에 쓰였는지", "어떤 게 곧 만료되는지" 시간 순서를 알지 못합니다.

---

### ② 이중 연결 리스트 (Doubly Linked List) — $O(1)$
* **역할**: "최근 사용 순서 줄세우기 (LRU 추적)"
* **동작 원리**:
  * 데이터들을 앞뒤 화살표(포인터)로 연결하여 기차처럼 이어 붙입니다.
  * 누군가 데이터를 조회(`GET`)하거나 수정(`SET`)하면, 그 기차 칸의 연결 고리만 끊어서 **맨 앞(Head: 가장 최근 사용)**으로 순식간에 옮깁니다.
  * 메모리가 꽉 차면? 순서대로 뒤질 필요 없이 **맨 뒤 칸(Tail: 가장 오랫동안 안 쓴 녀석)**만 톡 떼어내 버리면 됩니다.
* **왜 $O(1)$인가?**:
  * 일반 배열은 중간 데이터를 빼서 앞으로 옮기려면 나머지 수만 개를 뒤로 밀어내야 하지만($O(N)$), 이중 연결 리스트는 앞뒤 링크 4개만 바꿔 끼우면 끝나므로 눈 깜짝할 사이($O(1)$)에 완료됩니다.

---

### ③ 최소 힙 (Min-Heap) — Peek $O(1)$, 갱신 $O(\log N)$
* **역할**: "만료 시간 알람 시계 (TTL 관리)"
* **동작 원리**:
  * 만약 키가 100만 개 있는데 "지금 시간 지난 거 있나?" 하고 1초마다 100만 개를 전부 검사($O(N)$)하면 서버가 터집니다.
  * 최소 힙은 나무(트리) 구조로 되어 있어, **"가장 먼저 만료될 시각(최솟값)"을 항상 맨 꼭대기(루트 노드)**에 올려둡니다.
* **왜 빠른가?**:
  * 서버는 맨 꼭대기 딱 1개만 봅니다($O(1)$).
  * 꼭대기에 있는 시간조차 "아직 5분 남았네?"라면, 그 아래에 있는 수십만 개의 데이터는 검사해 볼 필요도 없이 안전하다는 걸 즉시 알 수 있습니다.
  * 만료된 걸 꺼내거나 새 만료시간을 넣을 때만 트리를 살짝 정돈하는 데 $O(\log N)$(100만 개 기준 약 20번 연산)밖에 안 듭니다.

---

## 2. 세 자료구조의 유기적 협력 흐름

세 자료구조가 따로 동작하는 것이 아니라, **해시맵의 엔트리(`RedisEntry`)가 이중 연결 리스트 노드와 힙 정보를 함께 참조**하여 유기적으로 동작합니다.

```text
[ 사용자가 "GET user:1" 요청 ]
         │
         ▼
 1. 해시맵(HashMap) 조회: O(1)
    └── "user:1 데이터 찾았다! 여기에 LRU 노드 주소도 함께 보관되어 있음"
         │
         ▼
 2. 이중 연결 리스트(Doubly Linked List) 이동: O(1)
    └── 해당 노드의 앞뒤 링크만 떼어내 '헤드 바로 뒤(MRU)'로 즉시 이동!
         │
         ▼
 3. 최소 힙(Min-Heap) 꼭대기 검사: O(1)
    └── 가장 일찍 만료될 꼭대기 노드만 엿보고(Peek) 아직 안 지났으면 검사 종료!
```

---

## 3. 작업별 시간 복잡도 요약

| 작업 | 담당 자료구조 | 시간 복잡도 | 설명 |
| :--- | :---: | :---: | :--- |
| **키로 값 찾기 / 저장** | **해시맵** | **$O(1)$** | 키를 해시 함수로 변환해 버킷에서 즉시 탐색 |
| **최근 사용 순서 갱신** | **이중 연결 리스트** | **$O(1)$** | 노드 링크 변경을 통해 맨 앞으로 이동 |
| **메모리 초과 시 LRU 방출** | **이중 연결 리스트** | **$O(1)$** | 꼬리(`Tail.prev`) 노드를 즉시 제거 |
| **만료 여부 확인** | **최소 힙** | **$O(1)$** | 최솟값(루트)만 엿보기(`peek`) |
| **새 만료 시간 등록** | **최소 힙** | **$O(\log N)$** | 힙 트리를 상향 재정렬(`heapify up`) |
